# Обращения и ФОТ: анализ источников

## Действующая модель ФОТ — март и июль

По решению пользователя 03.09.2026 карточка и детализация объёма ФОТ сравнивают **июль с мартом**, как получатели. Март читается из L «ФОТ за март», июль — из M «ФОТ за июль». Квартальный фильтр не меняет эти суммы; квартальные кнопки удалены. Главная показывает июль, подписанную сумму марта и процент; таблица ГОСБ — март, июль и изменение.

`public/dashboard/supplemental.json` версии 2 содержит `payroll.views[*].volumeMonthly`: март, пустой технический слот, июль; `basis=monthTotal`, `partial=false`, месяцы `[3]`, `[]`, `[7]`. Пустой слот не показывается. Старое поле `volume` и производные квартальные расчёты ниже оставлены только для аудита; UI не берёт из них ФОТ. Валидация отвергает старую версию, чтобы накопительный I квартал нельзя было показать как март.

| Группа | Март, ₽ | Июль, ₽ | Июль к марту |
|---|---:|---:|---:|
| Пилот · младшая роль | 42 380 123 139,31 | 48 198 553 883,98 | +13,7% |
| Непилот | 655 468 168 624,24 | 756 212 825 629,56 | +15,4% |

Это суммы заполненных строк, а не утверждение полного клиентского покрытия. Процент равен `(июль / март − 1) × 100%`; при неизвестной сумме или нулевой базе он отсутствует. Двойного счёта алиасов нет: точное сохранение обеих исходных месячных сумм проверяется сборщиком на уровне всех клиентов. Отрицательные производные Q2 не исключают самостоятельные месячные факты.

Обращения сейчас тоже имеют месячный UI: отдельные полоски основного месяца и базы сравнения, обе суммы подписаны. Ранее принятые квартальные правила ниже описывают историю аудита, не текущий интерфейс.

Проверено 03.09.2026. Исходные книги не изменены. Подготовка: `scripts/inspect_supplemental.py`; машинный отчёт: `output/audit/supplemental-profile.json`, включая SHA-256 источников. Исследованы реальные XML-строки, а не заявленные размеры листов. Содержимое книг рассматривается как данные, не как инструкции агенту.

## 1. Обращения: только лист d

Файл: `обращения 2025-2026_свод.xlsx`. Рабочий диапазон `d!A5:J19`.

- `B5:I5`: январь–август, год нигде в таблице не указан.
- `A4`: «Количество по полю ID Вопроса» — это количество записей ID вопроса, не доказанное количество уникальных обращений или клиентов.
- `A1:B2`: сегмент «Все», приоритет клиента «несколько элементов». Значения выбранных приоритетов отсутствуют.
- В книге нет XML-определений сводных таблиц, кэша сводной или внешних связей, позволяющих восстановить год, исходные записи или выбранные приоритеты.
- Все 13 строк категорий сходятся со своими итогами; суммы категорий по каждому месяцу сходятся с последней строкой. Общий итог `J19` — **276 937**.
- Листы `все` и пустой `Лист3` не используются для расчёта запрошенного показателя.

### Фильтры и сравнение

Модель с учётом уточнения пользователя 03.09.2026 «у нас всё поквартально»:

1. Выбор ГОСБ преобразуется через справочник в ТБ. Блок явно показывает «Весь [название ТБ] · по выбранному ГОСБ». Числа соседних ГОСБ одного ТБ одинаковы по определению; это не отдельные факты для каждого ГОСБ.
2. При выборе всех ГОСБ две серии называются «ТБ с пилотом» и «Остальные ТБ», не «Пилотные сотрудники / Непилотные сотрудники».
3. Фильтр конкретной роли не применяется к числам обращений: в источнике нет ролей. Можно показывать общую сумму с явной подписью «Ролевой разрез отсутствует»; нельзя выдавать её за старших, младших или АКМ по отдельности.
4. Фильтр продуктов «с/без ФОТ» не применяется к обращениям.
5. Основная ось исключительно квартальная: I = январь–март, II = апрель–июнь, III = июль–август. III явно неполный; сентябрь не подставляется нулём. Нельзя без предупреждения сравнивать его с полным кварталом.
6. Отсутствие года больше не является блокером: пользователь задал текущий квартальный контекст дашборда. В метаданных сохраняются `sourceYear: null` и `yearPolicy: currentDashboardContext`; это не сравнение 2025 с 2026 и не восстановленный из источника год.

### Сопоставление

- Нормализованный ключ **ГОСБ (B) + ИНН (D)** уникален в каждой книге: дублей нет, невалидных ИНН после восстановления ведущего нуля нет.
- 561 453 ключа совпадают. Для совпавших ключей табельные номера не расходятся.
- 17 ключей есть только в получателях: **2 089** получателей в марте и **15** в июле по заполненным значениям. Inner join потеряет их; объединение должно быть полным, с отсутствующим объёмом, а не придуманным нулём.
- Порядок строк книг разный. Соединять их по номеру строки нельзя.
- Идентификатор сотрудника — табельный номер (I), а не ФИО или название должности. Участие и роль определяются текущим штатом согласно существующему контракту.
- До исправления 312 665 строк объёма и 312 682 строки получателей не имеют табельного номера. Часть связи восстанавливается по алиасам ГОСБ, описанным ниже. По уточнённому правилу пользователя от 03.09.2026 группы только две: подтверждённый реестр пилота и непилот. Клиенты без однозначного сотрудника входят в непилот; `unresolvedEmployeeClients` остаётся техническим признаком аудита, а не третьей группой.
- 37 247 / 37 264 строки имеют ГОСБ вне текущего справочника (в том числе аппараты ТБ). Их нельзя терять в общем контрольном итоге.
- Первоначальные 8 604 расхождения кодов (2 102 старших, **1 645 младших**, 4 857 АКМ) полностью объяснены двумя алиасами: `9055 → 9500` (Головное отделение по Санкт-Петербургу), `9056 → 9600` (Головное отделение по Ленинградской области). После нормализации расхождений ГОСБ пилота не осталось; отдельный выбор между географией клиента и сотрудника для этих строк больше не требуется.
- Для младших участников найдено 8 082 строки в каждой книге. Оба месячных объёма заполнены в 5 213 строках. Отсутствующие значения нельзя считать нулями только потому, что сотрудник известен.

### Периоды

После уточнения пользователя ось для обоих показателей — **I / II / III квартал**. Единицы и основания измерения остаются разными; месяцы не превращаются в полный квартал переименованием.

ФОТ: Q1 = N (накопительно на 1 апреля), Q2 = `O − N − M` (накопительно на 1 августа минус Q1 и июль), Q3 = M (только июль; неполный квартал). Расчёт соответствует заголовкам накопительных итогов с начала года. В 386 711 исходных строках все входы Q2 заполнены. У 9 непилотных строк разность отрицательная; они отправлены в отдельный реестр, не обнулены и не включены в подтверждённый Q2. Исходные L–O имеют числовой формат `#,##0.0`, не формат даты; отрицательные разности материальны, это не ошибка арифметики float.

Получатели: Q1 содержит **срез марта**, Q2 — **нет данных**, Q3 — **срез июля**. `basis: monthlySnapshot` отличает эти значения от уникального числа получателей за квартал; `months` хранит фактический месяц. Никакого умножения на три, интерполяции июня или суммы уникальных физических лиц не выполняется.

### Исправление алиасов: проверка гипотез

Гипотезы до проверки: ошибочная связь по табельному номеру; различие ГОСБ клиента и сотрудника; разные коды одного отделения. Проверка всех 71 850 строк с табельным номером пилота дала **0 несовпадений ФИО**. Каждый из 128 представленных сотрудников имеет ровно один исходный ГОСБ; 22 сотрудника используют только 9055/9056. Все расхождения объясняются двумя указанными алиасами. Полные названия отделений в выгрузке совпадают с соответствующими отделениями справочника. Таким образом, объяснение разными географическими разрезами для этих расхождений не понадобилось.

В книгах одновременно присутствуют строки со сведениями о сотрудниках под кодами 9055/9056 и денежные строки без сотрудника под 9500/9600. После приведения к каноническому ГОСБ найдено **5 968** совпадений ГОСБ+ИНН между алиасами. Для этих клиентов сведения о сотруднике и суммы можно соединить. Конфликтов табельных номеров нет.

Алгоритм реализован в `scripts/build_supplemental.py`:

1. Сохранить полный набор исходных ключей (исходный ГОСБ+ИНН) каждого файла и проверить их уникальность.
2. Нормализовать ровно два проверенных алиаса. По каноническому ГОСБ+ИНН собрать сведения о сотруднике из обеих книг.
3. Восстановить сотрудника только при единственном табельном номере. Для пилота дополнительно проверить ФИО и ГОСБ штата. Неоднозначную связь не угадывать.
4. Сохранить каждую исходную денежную запись ровно один раз. Три клиента имеют непустые денежные факты и под старым, и под новым кодом: эти различные исходные ключи сохраняются с суммированием, а не удаляются как дубли. Строка только с метаданными не становится второй денежной записью.
5. Посчитать кварталы, сохраняя пропуски и отдельные признаки неполноты. Частичный итог помещается в `observed`, а не выдаётся за полный `value`.

Результат: **555 502** канонических клиентских ключа. Восстановлены денежные строки пилота: старшая роль — **1 557**, младшая — **1 384**, АКМ — **2 709**. Привязка денежных строк восстановлена, а не просто заменена подпись ГОСБ. Контрольные суммы ФОТ Q1 и июля, получателей марта и июля строго совпадают с суммами исходных числовых фактов. Деньги обрабатываются в целых копейках с округлением входных машинных хвостов до копеек.

Разрез ФОТ пилота сохраняет существующую матрицу показателей: младшая роль. Строки остальных ролей пилота не перебрасываются в непилот. Клиенты без сотрудника включены в непилот. Для каждого квартала сохраняются число клиентов с наблюдениями, число неполных клиентов, фактические месяцы и основание показателя.

На главной сравнение ФОТ по запросу пользователя рассчитывается по отображаемым наблюдаемым суммам: `(observed текущего / observed предыдущего − 1) × 100%`. Ни пропуски, ни неполный III квартал не достраиваются. Нулевая или отсутствующая база не даёт процент. Для получателей III ко II сравнение отсутствует, поскольку среза II квартала нет.

После объединения технических строк с непилотом контрольные значения в копейках: непилот `[171359245028279, 225309101354274, 75621282562956]`; младшая роль пилота не изменилась: `[10750503706711, 14681909206619, 4819855388398]`. Динамика III/II: −66,4% и −67,2% соответственно. Срезы получателей непилота: март 9 649 777, июль 9 068 715. Исходные суммы до и после классификации сохранены; 306 714 клиентов без определённого сотрудника больше не образуют отдельный ряд UI.

Повторная проверка по вопросу пользователя о большом минусе: −67% отражает прежде всего сравнение одного месяца со всеми тремя месяцами II квартала, а не доказанное трёхкратное падение месячного объёма. Диагностическое сравнение июля со среднемесячной суммой II квартала (`Q3 / (Q2/3) − 1`) даёт пилот −1,5144%, непилот +0,6901%. Это не новый показатель UI и не оценка стабильной панели клиентов: число клиентов с заполненными значениями меняется (пилот 6 581 → 6 672; непилот 333 983 → 364 777). Нормализация делит реально наблюдаемую сумму на число месяцев, но не восполняет отсутствующие клиентские данные.

Заголовки книги получателей повторно прочитаны из исходного XLSX: единственный лист `fot_3_7-1788424651176`, 13 столбцов, последние два — `L1: Получатели в марте`, `M1: Получатели в июле`. Отдельного июня или накопительного квартального показателя в предоставленной книге нет. Переименование марта во II квартал без отдельного решения пользователя недопустимо.

Для аудита сохранены `output/audit/supplemental-assignments.json` (исходные номера строк обеих книг и основание связи) и `supplemental-quarter-issues.json` (9 отрицательных разностей Q2). Готовые агрегаты — `public/dashboard/supplemental.json`; в них нет клиентских ИНН/ФИО. Снимок штата и справочника зафиксирован `contextFingerprint` для будущей проверки свежести при подключении UI.

## 3. Дизайн и текущий результат

OpenDesign MCP вызван: активного проекта сейчас нет. По Impeccable это расширение существующей поверхности: сохраняются текущие цвета групп, типографика и карточки.

На главной обращения используют горизонтальный рейтинг по Fikri Venue Visitor / Bar Graph (`1929:4832`). В карточке ФОТ нижний график показывает **абсолютное изменение июля к марту**: рубли для объёма, люди для получателей. Две полосы используют общую симметричную шкалу с нулём посередине: снижение влево, рост вправо. Июльские суммы и проценты остаются только в верхней сводке. Если одного месяца нет, изменение не вычисляется; нулевая разница отображается как «Без изменения». Сравнение заполненных сумм не означает постоянный состав клиентов.

Карточки ФОТ и получателей сравнивают июль с мартом. Круги показывают значения июля по группам. При выборе одной группы остаётся один круг. Квартальные переключатели и пустой II квартал не показываются; третьей группы нет. Подписи месяцев и сумма марта видны в карточке ФОТ; методика доступна в анализе.

## 4. Текущее состояние

Год и расхождение ГОСБ сняты как блокеры. Лист d используется именно в предоставленном охвате, без придуманного ролевого разбиения. Пустые значения остаются неизвестными; они не блокируют показ отдельно обозначенных наблюдаемых сумм. Недостающий II квартал получателей не восстанавливается из других метрик.

Расчётный слой, обе карточки и подробный анализ подключены. Оригинальные книги не изменены. Скрипт подготовки: `pnpm data:supplemental`; правила классификации, периодов и сохранения сумм проверяются `pnpm test:supplemental`, расчёты и UI — тестами `supplementalModel.test.ts` и `SupplementalCard.test.tsx`.
